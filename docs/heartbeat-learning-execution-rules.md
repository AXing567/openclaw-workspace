# 心跳学习执行准则（OpenClaw 智力提升）

更新时间：2026-03-22

目的：把 `HEARTBEAT.md` 里“空闲时自行学习提高 openclaw 智力的知识并沉淀到本地”这件事，收敛成低打扰、可累计、低 token 成本的执行规则。

## 1. 心跳里的“学习”应该学什么

优先级从高到低：

1. **直接提升后续执行质量的知识**
   - 工具边界
   - 工具选路
   - 安全/审批语义
   - 子代理与长任务编排
   - 技能（skills）与插件（plugin）的职责划分

2. **直接提升工作区可维护性的知识**
   - memory 结构
   - 文档组织方式
   - 长期知识如何沉淀为短笔记/规则/模板

3. **暂不优先的内容**
   - 大而泛的概念性学习
   - 与当前 OpenClaw 实际使用无关的理论扩展
   - 高 token、低复用的漫无目的通读

## 2. 心跳学习的默认执行方式

### 2.1 默认做轻量沉淀，不开大工程

心跳不是主任务窗口。默认只做这些轻量动作：
- 读 1~3 份已有本地笔记或官方文档摘录
- 抽取 3~8 条高价值原则
- 写入一个短文档、补丁笔记，或更新当天 memory

除非用户明确要求，不要在心跳里主动展开：
- 大规模重构
- 长链路调研
- 多轮外部 API 消耗
- 高风险配置修改

### 2.2 优先“整理已有知识”，其次才是新增知识

顺序建议：
1. 先看 workspace 里是否已有相关沉淀
2. 先合并、压缩、去重
3. 不足时再补充新学习

原因：
- 这样更省 token
- 更容易形成真正可复用的本地知识库
- 避免每次心跳都重复造轮子

## 3. 适合在心跳中反复强化的核心认知

### 3.1 工具优先，不绕路
- 能用一流工具就不用 shell 模拟平台能力
- 网页轻抓取优先 `web_search/web_fetch`
- 需要交互、强 JS、反爬页面时切 `browser`
- 长任务执行用 `exec + process`
- 多代理协作用 `sessions_spawn`

### 3.2 结构化选路比“知道很多”更重要
真正提高“智力”的，不是堆知识点，而是让自己形成稳定选路：
- 这是网页抓取，还是浏览器交互？
- 这是同步小任务，还是后台长任务？
- 这是普通文档沉淀，还是值得 skill 化？
- 这是内部安全动作，还是需要先征得同意的外部动作？

### 3.3 技能数量要克制
- skill 会进入系统提示，带来固定 token 成本
- 只有高频、稳定、流程明确的任务才值得 skill 化
- 平台能力扩展属于 plugin，不属于 skill

### 3.4 心跳产出应偏“规则化”
比起写一堆零散感想，更应该产出：
- 执行准则
- 决策清单
- 选路规则
- 反模式列表
- 文档索引

因为这些更容易在未来任务中直接复用。

## 4. 心跳学习后的落地格式

优先采用以下产物之一：
- `docs/*.md` 的短笔记
- `memory/YYYY-MM-DD.md` 的当天学习记录
- `MEMORY.md` 中值得长期保留的原则
- 某个现有文档的增补，而不是重复新建同主题文件

建议篇幅：
- **短而硬**，一次心跳新增 10~60 行就够
- 重点写“以后怎么做”，少写“我今天看了什么”

## 5. 什么时候应该保持安静

即使完成了学习，也不一定要打扰用户。
以下情况更适合直接安静结束：
- 深夜/清晨
- 只是完成了一次常规知识整理，没有新结论
- 产出只是局部补充，不值得主动汇报
- 距离上次主动汇报很近

以下情况更适合主动汇报：
- 新形成了一条会显著改变后续做事方式的原则
- 修正了过去容易犯错的执行模式
- 形成了可直接复用的模板/规则/工作流
- 发现了配置、安全、权限、工具边界上的重要风险点

## 6. 反模式

不要把心跳学习做成下面这些样子：
- 每次都重复阅读同一批文档却没有新沉淀
- 只记“今天学了 XX”，没有留下以后可执行的规则
- 为了显得忙而做大工程
- 深夜也频繁主动打扰
- 把“学习”误做成“未经请求的大范围配置修改”

## 7. 当前可执行结论

根据当前已有笔记，后续心跳学习优先围绕这些方向滚动增强：
- OpenClaw 工具选路规则的进一步压缩与模板化
- skills / plugins / docs / memory 的职责边界
- 子代理、长任务、监督回报机制的更优实践
- 审批与安全边界的可操作化说明

核心原则一句话版：

> 心跳里的学习，不追求大而全；追求把高频判断压缩成未来可直接复用的本地规则。
