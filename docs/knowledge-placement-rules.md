# 知识落位规则：Skill / Docs / Memory / Workspace Notes

更新时间：2026-03-22

目的：避免把知识乱放。不是所有内容都该进 skill，也不是所有经验都该进 MEMORY.md。

## 1. 一句话分工

- **Skill**：把“高频、稳定、可复用的任务流程”固化成可触发的执行说明
- **Docs**：把“某主题的结构化知识”沉淀成长期可读笔记
- **memory/YYYY-MM-DD.md**：记录“今天发生了什么、今天学到了什么、今天做了什么决定”
- **MEMORY.md**：只保留“长期稳定、会改变未来行为的记忆”
- **TOOLS.md**：记录当前环境特有的本地操作备忘（设备名、SSH、习惯、工具约定）

## 2. 什么该做成 Skill

只有同时满足这些条件，才值得做 skill：
- 会重复发生
- 触发语义清晰
- 执行步骤相对稳定
- 未来多次复用时，skill 比普通笔记更省脑力

适合 skill 的例子：
- 某类标准调研流程
- 某类稳定的诊断流程
- 某类固定格式的产出任务

不适合 skill 的例子：
- 只发生一次的项目背景
- 仍在快速变化的方法
- 只是一些概念总结，没有明确执行流程
- 过于宽泛、什么都想管的“万能技能”

## 3. 什么该写进 Docs

适合 `docs/` 的内容：
- 官方文档学习沉淀
- 某工具/系统/流程的知识卡片
- 对比分析、设计原则、工作流说明
- 以后可能反复查阅，但不适合进入系统提示词的内容

判断标准：
- 值得以后读
- 但不值得每轮都注入上下文

换句话说：
> docs 是“知识库”，skill 是“执行器说明”。

## 4. 什么该写进 daily memory

适合 `memory/YYYY-MM-DD.md` 的内容：
- 今天做了什么
- 今天新增了什么笔记/规则
- 用户今天表达了什么偏好、决定、否决
- 今天遇到的阻塞和阶段性结论

daily memory 是原始日志，不要求高度抽象。
它的价值在于：给未来几天内的连续任务保留上下文。

## 5. 什么该升级进 MEMORY.md

只有下面这些内容才适合进长期记忆：
- 用户稳定身份信息
- 用户长期偏好
- 用户明确的边界/禁区
- 已反复验证、跨任务通用的方法原则
- 会长期影响我做事方式的判断

如果一条信息：
- 容易过期
- 依赖某次具体任务
- 只是今天的学习记录
- 未来不一定还成立

那就不要进 `MEMORY.md`。

## 6. 什么该写进 TOOLS.md

`TOOLS.md` 不是知识库，而是环境速查表。
适合放：
- 设备名与别名
- 主机、路径、SSH 入口
- 本地工具特殊用法
- 用户明确要求的操作约定

不适合放：
- 抽象原则
- 长篇学习笔记
- 与环境无关的通用知识

## 7. 一个简单决策树

遇到一条新信息时，按这个顺序判断：

1. **它是不是“今天发生的事”？**
   - 是 → `memory/YYYY-MM-DD.md`
2. **它是不是“长期稳定偏好/原则/边界”？**
   - 是 → `MEMORY.md`
3. **它是不是“某主题的结构化知识”？**
   - 是 → `docs/*.md`
4. **它是不是“环境特有的操作备忘”？**
   - 是 → `TOOLS.md`
5. **它是不是“高频且稳定的任务流程”？**
   - 是 → 考虑做 `skill`
6. **都不是**
   - 先不要硬写，等更明确再落位

## 8. 核心反模式

避免这些常见错误：
- 把一次性经验写进长期记忆
- 把概念笔记误做成 skill
- 把项目背景塞进 TOOLS.md
- 为了“显得聪明”而增加过多 skills
- 在 docs 已有内容时重复新建同主题文件

## 9. 当前执行启发

后续心跳里，如果是“学习提高 OpenClaw 智力”：
- 优先产出 docs 级规则笔记
- 只把真正稳定的方法论升级进 MEMORY.md
- 只有流程反复出现后，才考虑 skill 化

一句话版：

> skill 负责复用流程，docs 负责存知识，daily memory 负责记今天，MEMORY.md 负责保留长期稳定判断。
