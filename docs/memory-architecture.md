# 记忆分层方案

更新时间：2026-03-20

## 目标
让 OpenClaw 的“长期记忆”只保留稳定、高复用、可直接指导行为的内容；把事件型、学习型、临时型信息下沉到 daily memory 或专题文档，降低长期记忆噪音。

## 分层原则

### 1. MEMORY.md 里应该保留什么
只保留下面几类：
- 用户稳定身份信息
- 用户稳定偏好与边界
- 已反复验证、未来高概率持续适用的工作原则
- 对我后续决策有长期影响的方法论

### 2. MEMORY.md 里不该堆什么
不应长期堆放：
- “今天学了什么文档”这类事件记录
- 某次任务的中间过程
- 还没稳定验证的技巧
- 过度具体、容易过期的临时实现细节
- 目录扫描、阶段汇报、一次性阻塞描述

### 3. daily memory 的职责
`memory/YYYY-MM-DD.md` 用来存：
- 当天发生了什么
- 用户的当日决策与否决
- 正在推进的阶段性事项
- 尚未提炼成长期原则的观察

### 4. docs/ 的职责
`docs/` 用来存：
- 某一主题的结构化知识沉淀
- 官方文档学习笔记
- 工作流说明
- 可复用 SOP 与知识卡片

## 当前推荐结构

- `MEMORY.md`
  - 长期身份 / 偏好 / 边界 /方法论
- `memory/YYYY-MM-DD.md`
  - 每日原始日志
- `docs/openclaw-*.md`
  - OpenClaw 主题知识沉淀
- `docs/memory-architecture.md`
  - 记忆系统自身规则

## 执行策略

### 写入 MEMORY.md 前先问自己
这条内容是否同时满足：
- 3 天后仍有价值
- 不依赖某次具体任务上下文
- 能直接改变未来行为
- 比写进 docs/ 或 daily memory 更合适

如果有一条不满足，优先不要进长期记忆。

### 压缩动作
长期记忆维护时，优先做三件事：
1. 合并重复原则
2. 删除事件型表述，改写成抽象原则
3. 把具体知识迁到 docs/

## 这次整理得到的结论

- 之前的长期记忆总体方向没错，但混入了一部分“学习记录式表述”。
- 以后学习官方文档时：
  - 专题知识优先写 `docs/`
  - 只有稳定、跨任务通用的行为原则才进入 `MEMORY.md`
- “记忆越多越聪明”是错觉；长期记忆质量比长度更重要。
