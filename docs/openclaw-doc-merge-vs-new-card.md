# OpenClaw 文档卡片：优先补旧文档，别滥开新卡

更新时间：2026-03-27

问题：
- 本地知识沉淀越来越多时，容易把每个小判断都写成一张新卡，导致文档数量膨胀、主题分散、检索成本升高。

结论：
- 当一个新认识只是已有文档的局部补充、边界细化或例外条件时，默认先补到旧文档，而不是新开一张卡。
- 只有在以下情况才值得单独建卡：
  - 主题可被独立检索，且不依赖读者先看前文
  - 会在后续任务中反复单独复用
  - 与现有文档不是“同一判断口的继续细分”，而是新的对象层

判断规则：
1. 先问：这是不是已有文档的一段新小节？如果是，优先 merge。
2. 再问：脱离原文后，这张卡还成立吗？如果不成立，不该独立成文。
3. 再问：新增文件会不会让目录更吵？如果会，优先追加到旧文件。

适用场景：
- heartbeat 学习
- docs 规则整理
- memory 提炼成规则卡

反模式：
- 仅因为能命名一个小点，就新建一张 md
- 同一主题拆成多张彼此高度依赖的卡片
- 目录里出现大量只差一个限定词的文件

一句话版：
> 文档增量默认先合并，只有真正独立的知识块才值得新开文件。
