# OpenClaw 文档卡片：文件名应反映内容边界

更新时间：2026-03-27

问题：
- 短卡文档增多后，容易出现“文件名只写了场景词或局部切面，但正文其实覆盖更宽规则”的情况。
- 结果是：搜文件名时不容易想到它；读内容时又发现比标题宽，造成检索成本上升。

结论：
- 卡片文件名优先表达“对象 + 判断边界”，而不是仅表达触发场景。
- 如果正文讨论的是通用规则，文件名就不要被某个单一场景绑死。
- 场景词（如 heartbeat）只在该规则明显只属于该场景时再放进文件名。

判断规则：
1. 先看正文在回答什么判断。
2. 再看这个判断是否只属于某个场景。
3. 若不是强场景绑定，文件名应写通用对象层，例如 docs、naming、scope、selection，而不是只写 heartbeat。

例子：
- 合适：`openclaw-doc-name-vs-content-scope-card.md`
- 偏窄：`openclaw-heartbeat-doc-gap-card.md`（若正文其实在讲通用命名/覆盖边界）

反模式：
- 用时间上下文命名长期规则
- 用触发来源命名通用判断
- 文件名比正文窄很多，导致未来检索时想不到

一句话版：
> 文件名要帮助未来检索到这条规则，而不是只记录它当时是在哪个场景下想到的。
