# OpenClaw Doc Title Patterns Card

## 好标题该长什么样
- 直接写对象 + 判断点：如 `write-vs-edit`、`read-strategy`
- 看到标题就知道这张卡解决什么犹豫
- 尽量让同类卡片命名风格一致，便于扫读

## 什么标题不够好
- 太泛：`tips`、`notes`、`thoughts`
- 太大：`openclaw-guide`、`workflow-summary`
- 太像过程记录而不是决策卡

## 命名时优先表达什么
1. 先表达“这是关于什么对象”
2. 再表达“解决什么判断”
3. 最后才考虑是否需要加 `heartbeat` 这样的场景前缀

## 一句话原则
标题不是装饰，是检索入口；先让未来的自己一眼找到。
