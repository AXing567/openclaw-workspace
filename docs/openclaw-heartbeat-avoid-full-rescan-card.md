# OpenClaw 心跳卡片：避免每轮全量重扫

更新时间：2026-03-27

问题：
- 心跳学习要求定期做本地沉淀，但如果每轮都从头全扫 `docs/`、`memory/` 或同一批规则文件，会浪费 token，也容易产出重复结论。

结论：
- 心跳默认采用“最小必要重读”策略：
  - 先读触发任务所必需的文件（如 `HEARTBEAT.md`）
  - 再抽一张最相关的已有卡片或短文档
  - 仅当发现冲突、缺口、或需要落地新规则时，才扩展阅读范围

执行规则：
1. 每轮先问：这次要补的是哪一个最小知识缺口？
2. 若已有同主题短卡能支撑判断，不回退到整组长文档。
3. 新沉淀应尽量补“新边界/新反模式/新选路”，而不是改写已知常识。
4. 如果只是确认旧规则仍成立，可直接静默结束，不必为了显得在学习而重复写文档。

适用场景：
- heartbeat 空闲学习
- 例行规则整理
- 想低成本保持对 OpenClaw 选路与边界的敏感度

反模式：
- 每 30 分钟把同一批文档重新读一遍
- 读得很多，但新增结论为零
- 只因为“空闲”就扩大阅读范围，没有明确小主题

一句话版：
> 心跳学习靠小缺口驱动，不靠全量重扫驱动。
