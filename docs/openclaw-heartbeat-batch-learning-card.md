# OpenClaw 心跳卡片：批量心跳按最后一次触发处理

更新时间：2026-03-27

问题：
- 同一会话里可能连续堆积多条 heartbeat 轮询消息。
- 如果逐条补做，会把同一时段的心跳学习重复执行，制造噪音和重复沉淀。

结论：
- 当多条 heartbeat 请求连续到达且内容等价时，执行上按“最后一次触发对应的当前时间”处理即可。
- 之前堆积的 heartbeat 不需要逐条补课，也不需要为每一条各做一次学习动作。

执行规则：
1. 先读取本轮指定的 `HEARTBEAT.md`。
2. 若 heartbeat 任务是周期性学习，而本次消息前已有同类未处理堆积，则只基于最后一条消息的时间判断是否需要做事。
3. 如果最后一条时间点适合做一次轻量沉淀，就做一次；否则直接返回 `HEARTBEAT_OK`。
4. 不为历史堆积 heartbeat 追加补写、补汇报、补刷存在感。

为什么：
- heartbeat 的价值在于“当前时点的低打扰检查”，不是补账系统。
- 周期任务按最后一个有效时点处理，更符合“不要 infer/repeat old tasks”的要求。

一句话版：
> 多条重复 heartbeat 堆积时，按最后一条处理一次，不逐条补做。
