# OpenClaw heartbeat cross-cluster switch card

## 默认判断
- heartbeat 连续做知识沉淀时，不能只在同一主题簇内部做更细切分；当最近几轮已经把某一簇补得很密，应主动切到另一个对象簇。
- 主题切换的目标不是“换个标题”，而是换一类未来会触发不同执行决策的问题。

## 什么时候该跨簇切换
- 最近 2-4 轮产物都还属于同一对象簇，比如 heartbeat 自身边界、节奏、重复控制。
- 当前再补一张，只会继续解释同一组默认规则，而不会新增明显不同的选路价值。
- workspace 里已经存在另一个成熟但可再压缩的对象簇，例如 status、tool routing、docs 维护。

## 怎么判断切换是有效的
- 新卡的检索入口与旧簇明显不同。
- 新卡能回答另一类执行问题，而不是给旧问题再加一个侧面注释。
- 即使读者没看最近 heartbeat 卡片，也能独立使用这张新卡。

## 实操规则
1. 先看最近几轮是不是都围着同一对象簇。
2. 如果是，就优先换到另一个对象簇，而不是继续在原簇做微分。
3. 若找不到足够清晰的新簇切入口，本轮就直接跳过，不强造主题。
4. 新卡优先写“切换后如何判断”，不要回头复述旧簇历史。

## 反模式
- 用不同标题继续写同一簇的边角规则。
- 表面上换了对象，实际内容仍在给旧簇补脚注。
- 为了保持频率，硬把稀薄判断口单独拆卡。

## 简写规则
- heartbeat 做到一簇够密后，要么跨簇，要么安静跳过。
