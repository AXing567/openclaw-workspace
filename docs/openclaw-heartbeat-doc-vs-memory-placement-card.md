# OpenClaw 心跳卡片：文档沉淀与记忆落点区分

更新时间：2026-03-27

问题：
- 心跳学习要求“沉淀到本地”，但沉淀内容并不都适合写进 `MEMORY.md` 或当天 `memory`。
- 如果落点混乱，后续会出现长期记忆臃肿、日记重复、规则分散的问题。

结论：
- 心跳产出的默认落点应按“复用范围”来分：
  - **`docs/*.md`**：面向未来任务复用的规则卡片、选路准则、反模式、工具边界。
  - **`memory/YYYY-MM-DD.md`**：记录今天做了什么、学到了什么、为什么做这次沉淀。
  - **`MEMORY.md`**：只保留会长期影响行为方式的稳定原则，不收纳每次微小学习结果。

落点规则：
1. 若内容是“以后遇到类似任务都能直接复用的规则”，优先写 `docs/*.md`。
2. 若内容只是“本次 heartbeat 做了什么”的会话痕迹，写当天 `memory`。
3. 若内容已经稳定到足以长期改变默认行为，再考虑提炼进 `MEMORY.md`。
4. 同一条微结论不要同时铺到 docs、daily memory、MEMORY 三处，避免三份重复。

反模式：
- 把每次 heartbeat 的普通学习都写进 `MEMORY.md`
- 把长期规则只放在当天 memory，导致后续难复用
- 同一结论在三个位置重复抄写，制造维护成本

一句话版：
> heartbeat 的本地沉淀，默认先落 `docs`；当天痕迹进 daily memory；只有稳定原则才升级进 `MEMORY.md`。
