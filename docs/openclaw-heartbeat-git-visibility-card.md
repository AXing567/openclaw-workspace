# OpenClaw heartbeat git-visibility card

## 默认判断
- heartbeat 下做本地沉淀时，产出不只要“文件写出来”，还要考虑是否处在当前 git 视角内；否则会出现文档存在、提交却看不见的割裂感。
- 发现 `git add` 报 pathspec 不匹配时，先判断为“工作区可见性问题”而不是文档没写成功。

## 常见原因
- 当前目录不是预期仓库根，git 看的不是同一个工作树。
- 文件写到了 workspace 里，但仓库实际跟踪的是更窄或不同的子树。
- 新文件落点没问题，问题出在 git 命令执行位置或 repo 边界判断。

## heartbeat 下的处理原则
- 先把知识沉淀落地到可见文件，不因为提交异常否定本轮产出。
- 把 git 异常当成独立问题记录，避免本轮 heartbeat 扩写成仓库排障任务。
- 后续若再遇到同类现象，优先先核对 repo root、tracked 范围、命令执行目录。

## 何时该停
- 一旦完成“写卡片 + 记一笔异常模式”，本轮就结束。
- 不在 heartbeat 里继续做大范围 git 勘探，除非 `HEARTBEAT.md` 明确要求。

## 简写规则
- 文档已落地 ≠ git 一定看得见；先区分产出成功和仓库可见性异常。
