# OpenClaw Heartbeat Late-Morning Cluster Switch Card

## 结论

当 heartbeat 已在同一主题簇上连续沉淀多轮，到了白天后续窗口（尤其上午后段），默认优先**换簇**而不是继续给原簇补边角。时间到了不代表同一话题还值得继续扩写。

## 适用场景

- `HEARTBEAT.md` 只要求空闲时做低打扰学习沉淀
- 前几轮已连续写过 heartbeat/边界/节奏/跳过条件相关卡片
- 当前没有新的外部触发、故障案例或明确问题单

## 判断口

先问三句：

1. **这次是否带来新的决策面？** 如果只是继续解释“何时跳过 / 何时继续 / 何时补位”，通常仍在原簇内打转。
2. **这次是否会减少未来误判，而不是只换个角度重写？** 真正值得写的是新增判断维度，不是把旧边界再拆细。
3. **是否存在更稀疏、覆盖面更高的主题可写？** 如果有，就该换簇；如果没有，也可以安静跳过，而不是硬续写旧簇。

## 默认动作

- **同簇已连续多轮 + 无新增触发**：换到别的 OpenClaw 主题，或直接 `HEARTBEAT_OK`。
- **同簇里确实出现新故障/新误判模式**：允许再写，但必须明确新增了什么判断维度。
- **只是因为时间又过了三十分钟**：不构成继续扩写同簇的理由。

## 为什么

heartbeat 的价值在于低成本扩大全局认知覆盖，而不是把一个局部主题打磨成碎片堆。到了上午后段还围着同一簇继续补卡，往往说明已经从“沉淀知识”滑向“维持产出感”。

## 实操口令

> 当同一主题簇已连续写过多轮，再到下一个白天 heartbeat，先判断“该不该换簇”，而不是先想“这一簇还能怎么再拆一张卡”。
