# OpenClaw Heartbeat Late-Night Quiet Boundary Card

## 结论

当 heartbeat 任务只是“空闲时做低打扰学习沉淀”时，深夜/凌晨窗口默认优先安静跳过；除非这次动作具有明显的时效性、能消除阻塞，或用户明确要求夜间也持续推进。

## 判断口

先看三件事：

1. **是否真有时效性**：比如快过期的信息、待验证的临界问题、会影响白天执行的阻塞。没有时效性，就不该为了凑频率在凌晨硬做。
2. **是否会制造噪音**：heartbeat 的目标是低打扰，不是把“每三十分钟一次”执行成机械 KPI。凌晨产出如果只是再补一张边界短卡，收益通常低于安静跳过。
3. **是否已经形成连续沉淀**：如果前一白天已经连做多轮本地整理，凌晨继续围绕同一类边界拆卡，往往只会加重主题过密和文档碎片化。

## 默认动作

- **无紧急性 + 仅常规学习沉淀**：直接跳过，回复 `HEARTBEAT_OK`。
- **有轻微价值但不紧急**：记住方向，留到白天或下一次更合适窗口再做。
- **明确紧急/阻塞/用户特别要求夜间推进**：可以执行，但要尽量单轮、闭合、低噪音。

## 为什么

`HEARTBEAT.md` 的“三十分钟一次”更像节奏提示，不是深夜也必须刷存在感的硬 SLA。夜间判断应优先服从“低打扰”和“不要重复旧任务”，而不是服从频率幻觉。

## 反例

以下情况不值得在凌晨继续做：

- 只是想再补一张与 heartbeat 边界有关的短卡
- 只是想维持“每半小时都有产出”的连续记录
- 只是因为当前无别的任务，就继续围绕同一文档簇微调表述

## 实操口令

> 深夜 heartbeat 遇到非紧急学习任务，先问“现在做，是否比白天做明显更值？”如果答案不明显是“值”，就安静跳过。
