# OpenClaw 心跳卡片：深夜学习默认静默

更新时间：2026-03-27

问题：
- `HEARTBEAT.md` 要求空闲时定期学习并沉淀，但凌晨时段如果只是常规整理，容易出现“做了事却不该打扰用户”的冲突。

结论：
- 在深夜/清晨（例如 23:00-08:00）执行心跳学习时，默认目标是“本地沉淀完成 + 对用户静默”。
- 只有在以下情况才值得主动打断用户：
  - 发现安全风险、权限边界问题、数据泄露风险
  - 发现会显著改变后续执行方式的重要规则
  - 发现需要用户尽快决策的阻塞或外部依赖

执行规则：
1. 先做轻量学习或整理，不展开大工程。
2. 产物优先写入 `docs/*.md`、`memory/YYYY-MM-DD.md` 或已有规则文档。
3. 若只是新增一张规则卡片、补充局部经验、没有紧急结论，则本轮心跳直接 `HEARTBEAT_OK`。
4. 不把“有产出”误等同于“必须汇报”。

反模式：
- 凌晨因为完成了普通文档整理就主动发长消息
- 没有新结论，只是为了证明在工作而打扰用户
- 把心跳学习做成需要用户同步跟进的半成品汇报

一句话版：
> 深夜心跳的默认最优解，不是多说，而是安静地把规则沉淀好。
