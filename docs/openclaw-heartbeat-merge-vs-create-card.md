# OpenClaw 心跳卡片：优先合并旧规则，别把知识切太碎

更新时间：2026-03-27

问题：
- 学习型 heartbeat 容易每次都新建一张小卡片，短期看有产出，长期会让 `docs/` 里出现大量近义规则，检索和维护成本反而上升。

结论：
- 心跳沉淀默认遵循“先并入已有主题文档，只有明显新主题才新建文件”。
- 知识密度不等于文件数量；能合并成一份更硬的规则，就不要拆成多张近似卡。

执行规则：
1. 先找同主题已有文档：heartbeat 执行、边界、静默、选题、输出格式等。
2. 若新结论只是对旧规则的一个补充角度，优先补到原文档中。
3. 只有在满足以下任一条件时才新建卡片：
   - 主题边界清晰，后续可独立复用
   - 原文档会因加入该内容而变得混乱
   - 新规则会被频繁单独引用
4. 若发现 docs 中已存在多个近义卡片，后续心跳应考虑合并/去重，而不是继续扩写分支。

反模式：
- 每次 heartbeat 都新建一张“只多一条判断”的卡片
- 同一主题拆成多个文件，文件名不同但规则几乎重复
- 为了证明在学习而制造目录膨胀

一句话版：
> 心跳学习的目标是提高可复用知识密度，不是把 `docs/` 变成碎片仓库。
