# OpenClaw Heartbeat Morning Restart Boundary Card

## 结论

heartbeat 在凌晨安静跳过后，到了早晨窗口，不应把“终于到白天了”自动等同于“现在必须继续写同一簇短卡”。是否重启学习沉淀，要先判断当前主题是否已经出现边界过密、价值递减或重复风险。

## 适用场景

- HEARTBEAT.md 只要求“空闲时”做低打扰学习沉淀
- 前一轮或前一天已经连续产出多张边界/规则卡片
- 当前时间从深夜切到白天，容易产生“该补课了”的错觉

## 判断口

### 1. 先问：今天继续写，是否是在补新的认知空白？

如果只是把昨天已经很密的 heartbeat 边界簇再拆细一层，不算新的认知空白，只是在延长同一主题链。

### 2. 再问：是否存在明确的新触发？

有以下任一项，才更值得重启沉淀：

- 新暴露出的工具误判
- 新版本行为变化
- 新增一个此前没有覆盖的决策分叉
- 某个旧卡片已明显不足以指导后续执行

如果没有新触发，只是时间到了早晨，不足以构成继续施工的理由。

### 3. 最后问：不做这一轮，会丢失什么？

如果答案只是“会少一条记录”，那通常不值得做；如果答案是“会让后续频繁犯同一种错”，那才值得落文档。

## 默认动作

- **只是从夜里切到早晨，但没有新触发**：跳过，回复 `HEARTBEAT_OK`
- **有新触发，但只需一句规则能澄清**：做一个单轮、闭合的小沉淀
- **需要连续扩写才能成立**：不适合 heartbeat，留到明确任务里处理

## 为什么

heartbeat 的目标不是维持文档产出的连续性，而是用最低打扰成本补真正缺的认知。夜里跳过后，早晨的首轮判断重点应是“是否值得重启”，不是“是否该补回频率”。

## 实操口令

> 早晨第一轮 heartbeat，先判断有没有新触发；没有，就别把凌晨的安静跳过视为待补欠账。
