# OpenClaw 心跳卡片：心跳学习优先最小读取

更新时间：2026-03-27

问题：
- 心跳任务要求空闲时持续学习，但如果每轮都大范围重读文档，会造成 token 浪费、重复整理和低效沉淀。

结论：
- 心跳学习默认采用“最小必要读取”策略：先读最可能产出新规则的短卡或局部文档，只在发现冲突、缺口或高风险边界时再扩展读取范围。

执行规则：
1. 先判断本轮要补的是“新知识”还是“旧知识压缩”。
2. 若只是压缩已有认知，优先读取已有短卡，而不是回到整份长文档。
3. 若已有短卡能支持本轮沉淀，则直接基于短卡新增一张更细的规则卡片或补充到现有卡片。
4. 只有在以下情况才扩大读取：
   - 发现规则冲突
   - 需要确认限定条件
   - 本轮主题涉及高风险操作或安全边界
5. 心跳的目标是留下可复用规则，不是证明自己“读了很多”。

反模式：
- 每次心跳都从头通读 docs 目录
- 为了找一句规则，反复重读长文档
- 只增加阅读量，不增加未来可执行的判断规则

一句话版：
> 心跳学习拼的不是读得多，而是用最少读取换来新的稳定规则。
