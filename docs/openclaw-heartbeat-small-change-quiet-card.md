# OpenClaw 心跳卡片：小增量学习默认不汇报

更新时间：2026-03-28

问题：
- 心跳里经常只会形成一个很小的新边界或补充规则。如果每次有一点点沉淀就汇报，会把常规维护噪音化。

结论：
- 当本轮学习产出只是“小增量修正”时，默认完成本地沉淀即可，不主动打扰用户。
- 只有当增量满足“显著改变后续行为、暴露重要风险、或需要用户决策”之一，才值得主动汇报。

判断标准：
- 小增量：
  - 只是补了一张短卡
  - 只是把旧规则说得更清楚
  - 只是新增一个局部反模式
  - 不会改变后续大多数任务的执行路径
- 大增量：
  - 新发现会改变工具选路
  - 新发现安全/审批/权限风险
  - 新形成高复用模板或稳定工作流
  - 需要用户拍板才能继续

执行规则：
1. 先判断这次沉淀属于“小增量”还是“大增量”。
2. 小增量：写入本地后直接 `HEARTBEAT_OK`。
3. 大增量：用简短消息说明“变了什么、为什么重要、建议怎么用”。

一句话版：
> 心跳不是日报系统；小修小补沉淀到本地就够了。
