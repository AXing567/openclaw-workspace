# OpenClaw 心跳卡片：工具受限时的退化策略

更新时间：2026-03-27

问题：
- 心跳任务要求“空闲时学习并沉淀”，但实际运行中常会遇到工具、权限、环境或时间窗口受限。
- 如果没有退化策略，执行容易变成无效试探：不停探测命令、目录或外部资源，却没有稳定产出。

结论：
- 心跳学习的核心不是“尽量多调工具”，而是“在当前约束下留下可复用沉淀”。
- 当关键工具不可用、成本过高、或当前时段不适合重操作时，应立即退化到本地轻量整理模式。

退化顺序：
1. **优先使用现成一流工具**
   - 轻网页：`web_search` / `web_fetch`
   - 重交互页面：`browser`
   - 长命令：`exec + process`
2. **如果受限或不划算，退化为本地沉淀**
   - 整理已有 docs / memory
   - 抽取规则、边界、反模式
   - 合并重复卡片，减少知识碎片
3. **如果连新增沉淀价值都不高，就安静结束**
   - 避免为完成 heartbeat 而制造低价值文档
   - 此时直接 `HEARTBEAT_OK`

判断信号：
- 不要因为一个命令失败，就把学习任务升级成环境排障任务
- 不要在深夜为了“显得在工作”而启动高噪音操作
- 不要把权限/审批受限误判成必须继续试探的理由

反模式：
- heartbeat 里反复目录遍历、命令试错、外网探测
- 新增一堆低密度文档，只是把同一句话拆成多张卡
- 在没有新结论时，仍然强行输出学习汇报

一句话版：
> 工具受限时，心跳应该优雅退化，而不是执着硬闯。
