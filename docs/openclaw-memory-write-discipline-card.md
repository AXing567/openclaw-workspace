# OpenClaw 记忆写入纪律卡片

更新时间：2026-03-27

## 结论

在 OpenClaw 里，`memory_search` / `memory_get` 解决的是“回忆前先检索”；但真正让记忆系统长期有效的前提，是平时就把应记的东西写进去。**不写，就没有可检索的长期上下文。**

## 该写什么

优先写这几类：
- 用户明确说“记住这个”
- 已做出的取舍、规则、边界、偏好
- 排查后得出的坑点、反模式、稳定做法
- 后续还会复用的工作流或判断口
- 会影响下次协作效率的项目信息

## 写到哪里

- 当天发生、偏原始过程：`memory/YYYY-MM-DD.md`
- 已经沉淀成长期稳定认知：`MEMORY.md`
- 更像通用规则、工具经验、选路卡片：`docs/*.md`

## 决策原则

1. **先记录，再指望以后回忆。**
2. **日记负责留痕，长期记忆负责提纯。**
3. **通用方法论别全塞进 MEMORY.md，应该放进 docs。**
4. **口头说“记住了”不算完成，文件里可见才算完成。**

## 反模式

- 只在回复里说“我会记住”，却不更新任何文件
- 把短期流水和长期原则混写，导致 MEMORY.md 越来越脏
- 遇到新经验只临时记在上下文里，不写入 workspace
- 把本该进入 docs 的通用规则硬塞进个人长期记忆

## 一句话版

> OpenClaw 的记忆系统不是“会记住”，而是“写进去，未来才能搜出来”。
