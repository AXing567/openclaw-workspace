# OpenClaw 插件安装判定清单卡

更新时间：2026-03-27

用途：
- 当用户一句话说“装个插件 / 安装某某插件”时，先快速判定到底该走 OpenClaw 插件安装，还是第三方工具安装，还是 skill/本地能力建设。

## 先问的不是“怎么装”，而是“它是什么”

按下面顺序判断：

1. **文档里有没有明确写 `openclaw plugins install <spec>`？**
   - 有：优先按 OpenClaw 插件处理。
   - 没有：继续往下判定。

2. **安装完成后，它会不会变成一个系统命令？**
   - 会，且文档写 `npm install -g` / `pip install` / `cargo install`：大概率是独立 CLI，不是 OpenClaw 插件。

3. **它是不是只是一个工作流说明、提示模板、skill 名称？**
   - 如果是：不要误导成“可安装 npm 包”。应先确认是 bundled skill、workspace skill，还是需要自己创建 skill。

4. **它是否需要被 OpenClaw 发现和托管？**
   - 需要：倾向插件。
   - 不需要，只要命令能跑：倾向独立工具。

## 默认输出格式

面对“帮我装 X 插件”，优先给自己一个三分法：
- 这是 **OpenClaw 插件**
- 这是 **独立 CLI / 外部工具**
- 这是 **skill / 本地流程能力**

只有类型判清后，才进入安装步骤。

## 价值

这张卡的目的不是增加解释，而是减少两个高频误判：
- 把独立工具错装成 OpenClaw 插件
- 把 skill 名字误当成可直接安装的包名

一句话版：
> 用户说“装插件”时，先做类型判定，再决定安装命令；不要把 plugin、CLI、skill 混成一类。
