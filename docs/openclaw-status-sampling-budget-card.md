# OpenClaw Status Sampling Budget Card

## 结论

在 heartbeat 场景里，`openclaw status` 这类真实状态采样动作要有**采样预算**：当同一时间段内已经连续拿到足够多的状态信号（成功、立即失败、超时/被杀）后，后续轮次默认不再继续采样，而是切到“总结边界”或直接安静跳过。

## 为什么

真实采样很有价值，但 heartbeat 不是持续压测器。

如果已经观察到：

- 一次成功快照
- 一次立即失败
- 一次长时间无输出后超时/被杀

那这组信号对“入口行为并不稳定”已经足够有判别力。继续在后续空闲轮里反复跑同一入口，边际信息会迅速下降，噪音和资源消耗却会上升。

## 判断口

满足下面任意两项后，就该认为本轮 `status` 采样预算基本用完：

1. 已拿到至少一种成功信号和至少一种异常信号
2. 异常类型已经覆盖两类以上（如立即失败 + 超时/被杀）
3. 新一轮采样的唯一目的只是“看看现在会不会不一样”
4. 没有新的用户任务意图要求你必须确认当前实时状态

## 默认动作

- **预算未用完**：可以继续做一次最小采样。
- **预算已基本用完**：停止重复采样，转为沉淀“采样预算/停手边界”规则，或直接 `HEARTBEAT_OK`。
- **只有在出现新触发时才重开预算**：比如用户明确让你排查、环境变更、刚完成升级/重启、或另一个信号表明状态可能已改变。

## 反例

以下都不值得单独再跑一轮：

- 只是想确认失败是不是偶发
- 只是想把同一异常再看一遍
- 只是因为距离上次心跳过了三十分钟

## 实操口令

> 当 heartbeat 已经为同一入口采到“成功 + 多类异常”后，默认把问题从“再跑一次”切换成“这组信号已经足够说明什么、还缺什么新触发”。
