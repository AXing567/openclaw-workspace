# OpenClaw Status Warning Wording Card

## 结论

当 `openclaw status` 显示系统整体可用、gateway 正常，但附带若干 warning 或 update available 时，回答和文档沉淀里要把它们表述成**需要后续处理的提示**，不要偷换成“当前系统异常”或“已经出故障”。

## 为什么单独记这一条

运行态文档很容易在总结时用力过猛：

- 看到 `warn` 就顺手写成“系统有问题”
- 看到 update available 就顺手写成“需要立即升级”
- 看到 next steps 多，就顺手把所有后续动作都说成默认必做

这样会把 `openclaw status` 的“总览 + 导航页”性质讲歪，后续排查口径也会变得焦躁和失真。

## 默认表述顺序

优先按这三层说：

1. **当前是否可用**：先明确核心运行面是否正常，例如 gateway 是否在线、服务是否可达、主流程是否可继续。
2. **有哪些提示**：再说 warning、update、audit 建议等，它们是提示层，不自动等于故障层。
3. **下一步处理建议**：最后只给一个与当前意图最相关的 follow-up，而不是默认全展开。

## 推荐措辞

- “当前主流程可用，但状态页给了若干 warning，属于后续处理提示。”
- “有更新可用，不等于当前版本不可用；是否升级取决于当前任务目标。”
- “安全审计提示需要分级看待，先区分建议项和会阻断当前操作的问题。”

## 避免的措辞

- “系统异常” —— 除非 status 真的显示服务异常或关键链路不可用。
- “必须立刻升级” —— 除非存在明确安全/兼容阻断证据。
- “这些 warning 说明 OpenClaw 坏了” —— 这是典型误导。

## 实操口令

> 先报可用性，再报提示项，最后只给一个最相关的下一步；不要把 warning 语言升级成故障语言。
