# OpenClaw 任务选路卡片

更新时间：2026-03-22

目的：把常见任务快速路由到更合适的能力，减少“先乱试再回头”的成本。

## 1. 网页相关：`web_*` 还是 `browser`

### 用 `web_search` / `web_fetch` 的情况
- 只是想找资料、看公开网页内容
- 页面主要是静态内容
- 不需要登录、不需要点击、不依赖复杂 JS
- 目标是“快拿到文本”，不是模拟真实浏览器

### 用 `browser` 的情况
- 需要点击、输入、翻页、上传、下载
- 页面强依赖 JS
- 页面结构复杂，普通抓取不稳定
- 需要看真实渲染后的 UI
- 要基于页面状态进行下一步操作

### 速记
- **拿内容** → 先想 `web_*`
- **做交互** → 先想 `browser`

## 2. 执行命令：同步 `exec` 还是后台 `exec + process`

### 同步执行就够的情况
- 命令几秒内能结束
- 只是看一个结果
- 不需要持续观察输出

### 用后台执行的情况
- 任务明显会跑很久
- 需要后续查看日志
- 需要轮询进度或中途停止
- 任务本身就是“启动一个持续进程”

### 速记
- **短命令** → `exec`
- **长任务 / 持续进程** → `exec + process`

## 3. 自己做，还是起子代理

### 直接自己做的情况
- 小修补
- 一次性查询
- 任务不复杂，不需要大量探索
- 上下文紧密依赖当前对话

### 起子代理更合适的情况
- 长任务
- 慢任务
- 可以并行拆分的任务
- 大规模代码探索、评审、重构
- 希望主线程保持轻量，不被阻塞

### 速记
- **短平快** → 当前会话直接做
- **慢、长、可并行** → 子代理

## 4. 写文档，还是做 skill

### 写 `docs/` 的情况
- 是知识、原则、总结、方案
- 以后值得查阅
- 但不需要每轮自动注入提示词

### 做 skill 的情况
- 是高频重复任务
- 触发条件清晰
- 步骤稳定
- 未来复用时值得让系统直接记住这套流程

### 速记
- **存知识** → `docs/`
- **固化流程** → `skill`

## 5. 写 daily memory，还是升级到 MEMORY.md

### 写 daily memory 的情况
- 今天刚发生
- 还没验证稳定性
- 只是阶段结论
- 是任务过程记录

### 写 MEMORY.md 的情况
- 长期稳定
- 能改变未来行为
- 跨任务通用
- 不是事件，而是原则/偏好/边界

### 速记
- **今天的事** → daily memory
- **长期稳定判断** → MEMORY.md

## 6. 要不要主动打扰用户

### 更适合主动汇报
- 发现明显风险
- 形成了会改变后续做法的新规则
- 有明确可执行结论
- 有用户现在就该知道的事项

### 更适合安静结束
- 只是常规学习沉淀
- 没有新增重要结论
- 只是局部整理
- 时间点不适合打扰（深夜/清晨）

## 7. 一个最小决策序列

拿到任务后，先问自己这 5 个问题：

1. 这是**拿内容**还是**做交互**？
2. 这是**短命令**还是**长任务**？
3. 这是**自己做**还是**起子代理**更划算？
4. 产出应该是**知识沉淀**还是**流程固化**？
5. 结果应该**主动汇报**还是**安静结束**？

## 8. 一句话版

> 先判断任务类型，再选工具；先选合适层级，再决定是否打扰用户。
