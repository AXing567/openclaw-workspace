# OpenClaw Web Research Fallback Card

## 适用场景
当需要做公开网页调研，但默认首选工具失效时：
- `web_search` 缺 API key 或返回 provider 错误
- `web_fetch` 因解析到特殊 IP / 目标站拦截而不可用
- `browser` 因本机无受支持浏览器而起不来
- 仍需要在当前回合内给出“有依据但带置信度”的结论

## 默认降级顺序
1. 先承认首选链路失效：`web_search/web_fetch/browser` 哪个坏了就记下来
2. 改用 `exec` 做**轻量公开抓取**：
   - 官方站首页/新闻页
   - 可直接 GET 的公开 JSON / quote / chart API
   - 能拿到静态 HTML 的行业媒体页
3. 如果搜索引擎结果页质量很差或被反爬：
   - 不要长时间纠缠 SERP 解析
   - 转向公司官网、可访问行情接口、已有本地文档
4. 数据仍不完整时：
   - 输出“方向性判断 + 明确假设 + 降低置信度”
   - 不把缺失数据伪装成已验证事实

## 能做什么
- 用 `requests` / `curl` 拉公开接口或静态页
- 用 Yahoo chart 这类免认证端点拿价格区间、52 周高低点、走势
- 从公司官网/行业站确认业务范围、产品结构、技术方向

## 不该怎么做
- 为了凑数据反复硬啃被拦截的搜索页
- 把行情走势当成基本面结论本身
- 在缺失年报核心财务时，装作已经精确核对过营收/利润

## 输出模板
- 已验证：我实际拿到的官网/公开接口信息
- 高概率判断：基于赛道结构、商业模式、价格走势作出的推断
- 未验证项：缺了哪些年报/公告/管理层口径
- 结论置信度：按证据完整度下调

## 一句话原则
首选工具失灵时，目标不是“假装全知”，而是用可访问证据把不确定性说清楚。
